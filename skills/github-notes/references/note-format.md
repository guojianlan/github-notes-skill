# 笔记格式

尊重目标仓库现有格式。没有约定时可使用以下结构，按实际问题增删栏目，不补造结论或验证记录。

```markdown
---
created: 2026-10-20
updated: 2026-10-20
tags: [主题]
status: source-reviewed
---

# 明确的研究问题

先说明结论、适用范围以及实际要解决的问题。

## 来源与依据

保留原始链接、相关文件和版本。分清源码观察与项目自己的宣称。

## 方案与取舍

说明可采用部分、依赖条件和暂缓部分。

## 验证与下一步

记录已完成的检查、仍需验证的关键点，以及下一次最小验证步骤。
```

补充验证结果时保留样本范围、日期、结果与局限。笔记中的建议、代码存在、模拟测试通过和真实运行验收是不同状态。

索引只需覆盖实际内容，条目链接使用相对路径。凭据、私人家庭材料或商业机密的保存范围以用户授权和仓库可见性为准；本工具的常见 Token/私钥特征检查只是一道辅助检查，不能识别所有敏感信息。
